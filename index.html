How it fits together

Running an assessment

Open the assessment, pick a framework from the dropdown, and fill in the customer details. Score each control for policy and implementation, and record what you saw in the two findings boxes. Set targets on the Goals tab — they drive the priority ranking on the Recommendations tab.

Save early and often: everything lives in the browser tab until you press Save JSON. One file per customer per framework.

Producing the report

Open the report builder and drop the saved JSON on it. Set the cover details, edit the drafted executive summary, choose which findings to include, then print to PDF. Save your settings to reuse the same house style next time.

Adding a framework

Drop the JSON into frameworks/ and add a row to frameworks/index.json. Anything named framework-<id>.json is found even without a manifest entry.

frameworks/
    index.json
    framework-csf.json
    framework-yourown.json

Framework files use "schema": 3 — groups containing sections containing controls, plus a flat item list carrying the question, recommendation and effort rating. Copy an existing file to see the shape.

Editing recommendations in the framework file changes the starting point for every future assessment. Editing one inside an assessment only affects that customer, and is flagged as tailored in the exports.

Nothing is uploaded. Every tool here runs entirely in your browser. Assessment data is read from and written to files you choose, and is never sent anywhere. The only outbound request any tool makes is for the framework files in this folder — and, if you set one on a report cover, the logo image from whatever host you point it at.
Single-file tools, no dependencies, no build step, no telemetry. Framework content is derived from the published standards and is provided as a starting point for professional judgement, not as a certified crosswalk.
